What is Workspace?

Workspace is the complete {{ brand_name }} platform — a full-stack SaaS application for creating, organizing, and collaborating on text documents. Think of it as a self-hostable alternative to note-taking apps, built with developer ergonomics in mind.

📝 Rich Text Editor

Built on CodeMirror 6 with custom extensions for sections, dates, formatting, and more.

👥 Real-Time Collaboration

Multiple users can edit the same page simultaneously using Yjs CRDTs over WebSockets.

🤖 AI-Powered Answers

RAG-based Q&A that searches your pages and generates answers using embeddings.

🔌 REST API

Full API access for automation, integrations, and building your own clients.

🏢 Multi-tenant

Organizations, projects, and fine-grained sharing at every level.

🚀 Production Ready

Not a demo — this is the actual codebase running {{ brand_name }} in production.

Quick Start

# Clone the repository
git clone https://github.com/hyperclast/workspace.git
cd workspace

# Copy env template and start everything
cp backend/.env-template backend/.env-docker
./run-stack.sh

That's it. The script spins up PostgreSQL, Redis, the Django backend, and the Vite frontend via Docker Compose. See the README for manual setup or production deployment.

FAQ

Why AGPL-3.0?

Let's address this directly: Workspace is licensed under the GNU Affero General Public License v3.0, not MIT or Apache 2.0. The AGPL is the strongest copyleft license the OSI recognizes, and we chose it on purpose.

We're a tiny team building something we're proud of. The AGPL lets anyone do almost everything: self-host, modify, contribute, build on top of it, learn from it. The one condition is reciprocity: if you modify the code and let people use it over a network, you have to give those people your modified source under the same license.

This isn't hypothetical. We've watched large cloud providers strip-mine permissively licensed projects: taking years of work from small teams, offering it as a service, and contributing nothing back. The AGPL doesn't forbid that, but it does make it a fair trade. Anyone who builds on our work has to share their improvements the same way we share ours.

Is this "open source"?

Yes, in the strict sense. "Open Source" has a specific meaning (the OSI definition), and AGPL-3.0 is an OSI-approved license. You can read, run, modify, self-host, redistribute, and learn from the code. Whatever you build on it has to pass the same freedoms on to its users.

Our standalone libraries like Firebreak are Apache 2.0 with no copyleft at all. We're not allergic to permissive licenses. We just think the core platform, the thing that pays our rent, deserves a license that keeps improvements flowing back instead of disappearing behind someone else's paywall.

If the AGPL doesn't work for you, for example because you need to keep your modifications private or your legal team won't touch AGPL code, we offer the same code under a commercial license.

Can I self-host this?

Anyone, including businesses: Yes, absolutely. Deploy it on your own infrastructure, run it on a VPS, spin it up locally. The code is all there: no artificial limits, no phone-home, no "enterprise features" held hostage. Running an unmodified copy for your own team carries no obligations beyond keeping the license notices.

If you modify it: the AGPL asks you to offer your modified source to the users you serve it to. If that doesn't fit how you work, a commercial license removes that obligation and adds support.

What's the difference between this and the hosted version?

Same codebase. The hosted version on {{ brand_name }} gives you managed infrastructure, automatic backups, and support — so you don't have to think about ops. Self-hosting means you're responsible for all of that, but you own your data and infrastructure completely.

Either way, the code is the same AGPL-licensed code. The choice is just about who runs the servers.

Do I need Redis and PostgreSQL?

For kicking the tires, SQLite works fine. For production or real-time collaboration, you'll want PostgreSQL and Redis. The README walks through the setup.

How does the AI Ask feature work?

Pages are chunked and embedded using OpenAI's embedding API. When you ask a question, we find relevant chunks via vector similarity, then generate an answer using the LLM with those chunks as context (RAG pattern). Bring your own API key.
